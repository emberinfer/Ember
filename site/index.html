The Ember project develops experimental, open-source software for an open, decentralized inference network. The network is open to independent operators contributing inference capacity. Submit signed execution evidence and receive valueless test Spark when sampled replay accepts the work and settlement finalizes.

What it is

Four kinds of participants, one ledger. Ember connects eligible inference hardware through signed work, sampled audits, and test-credit accounting.

Gateway

The consumer-facing entry point. Accepts inference requests, reserves test credit, routes work, and returns results.

Inference nodes

Run models on their own hardware through engine adapters, execute requests, and commit signed evidence for every token.

Auditors

Replay sampled work and compare signed evidence. A numerical rejection requires confirmation by a different assigned auditor before slashing; sampling does not detect every deviation.

Ledger

A CometBFT chain that holds accounts, Spark balances, stake, receipts, verdicts and settlement — the single source of truth.

Why Ember

Inference supply today is concentrated and opaque. Ember exists to make it open and verifiable.

Supply is locked in a few clouds. Ember lets any operator join permissionlessly — stake, register, serve — on hardware from a data-center GPU to a small edge board.

Remote execution is hard to verify. Signed evidence and sampled replay support probabilistic fraud detection before settlement; they do not prove every computation correct.

Open contributors need shared accounting. The ledger records Spark balances, holds, and policy penalties. Testnet Spark is valueless test credit; consensus and audit trust assumptions still apply.

One engine never fits all hardware. A unified Engine SPI with graded evidence lets PyTorch, vLLM, llama.cpp and future engines serve side by side.

Use it

Start with the signed v0.1.0 release. Linux amd64 or arm64, Python 3.12 with venv/ensurepip, OpenSSL with Ed25519, tar, sha256sum and curl are required. The installer needs no root access.

Download your architecture (replace amd64 with arm64 on ARM64), then verify. EMBER_RELEASE="https://github.com/emberinfer/Ember/releases/download/v$EMBER_VERSION"

  curl -fLO "$EMBER_RELEASE/$file"
done
openssl pkey -pubin -in release-signing.pub -outform DER | sha256sum
openssl pkeyutl -verify -pubin -inkey release-signing.pub \
  -rawin -in SHA256SUMS -sigfile SHA256SUMS.sig
sha256sum --ignore-missing -c SHA256SUMS
tar -xzf "ember-$EMBER_VERSION-linux-amd64.tar.gz"
cd "ember-$EMBER_VERSION-linux-amd64"
./install-release.sh --role node --prefix "$HOME/ember" --python python3.12

Download the pinned model revision using the Quickstart model command. Then configure and serve. A public network is forthcoming: access endpoints and participation details will be announced separately, and this site publishes no live network configuration.

Run a node

Provide compute, receive valueless test Spark per settled request. Enrollment stakes the minimum and registers your identity automatically. The Quickstart carries the current configure, fund and serve commands for a live network.

Exit and recover stake

Stop serving and automatic restart. Keep your identity. Wait for registration expiry, unbond all stake, wait for the release height, then claim. Use the complete exit commands and confirm zero stake and no pending unbondings.

For a disposable smoke check, select a short registration lease before first join as documented; the default lease is 200000 finalized blocks.

Models & engines

Ember restricts neither the model nor the inference framework. Three mechanisms keep that freedom verifiable.

  • Engine SPI adapters. A model runs wherever an adapter runs it — Transformers, vLLM and llama.cpp today; third parties can ship adapters that pass the public conformance kit.
  • Immutable execution Profiles. Each model is pinned on-chain by its weights-manifest hash, tokenizer hash and runtime fingerprint. A new model or runtime enters the network as a new Profile, registered on-chain — not as a config change.
  • Operators bring their own weights. The network never distributes weights. Nodes obtain them from the model's publisher (e.g. Hugging Face) and the Profile hashes verify them before serving.

Status & limitations

  • Working today: decentralized ledger with slashing, engine decoupling with a conformance kit, cross-device sharding with failover, public-internet hardening, signed reproducible releases.
  • Released: v0.1.0 signed, reproducible builds for Linux amd64 and arm64; profile artifacts are signed and verifiable from the repository.
  • Governance and security: validators are currently operated by a single organization; no third-party security audit yet. Validator admission and consumer account custody remain operator controlled.
  • Performance and privacy: CPU serving is slow for long requests; the GPU profiles are the primary path. Short-request settlement does not establish production throughput or a service guarantee. Gateways, executors and auditors see the plaintext needed for their roles.
  • Test credit only: testnet Spark is valueless — no price, no exchange, no returns. No public mainnet or production SLA.
